🧩 Stub 模式 — 資料源尚未就緒也能繼續

每個 P-step 開始時，Claude 會詢問對應的資料庫連線是否可用。若尚未開放，可選擇 Stub 模式：API 端點照常建立，暫時回傳靜態假資料，前端可以立即開始開發。待資料庫就緒後，只需替換 Repository 層即可，API 合約完全不變。

⚙️ 設定檔（選用）

在專案根目錄建立 .vba-modernizer.yml 可略過 D-1 至 D-5 互動問答。

.vba-modernizer.yml
target: Vue 3-python        # Vue 3-python | Vue 3-node | python | node
source: original/TEST.XLS
output: migrated/
decisions:
  d1: Vue 3-python
  d2: keep-existing
  d3: xlsx
  d4: localstorage
  d5: batch-errors
exclusions:
  - Module1            # 跳過空模組
risk_threshold: medium   # medium 以上列入 REVIEW_QUEUE
test_generation: true

❓ FAQ

問題答案
支援哪些 VBA 系統？任何 .xlsm / .xls / .xlam / .bas / .cls / .frm，財務、HR、庫存、製造等所有領域
可以只做 Plan 不寫程式碼？可以。Phase 2 完成後停下，把三份 HTML/MD 文件交給開發團隊照計畫實作
每次都要從 Phase 1 重新開始？不用。.vba-extracted/inventory.json 存在時 Phase 1 自動跳過
不懂 Python/Node 可以用嗎？Phase 1–2 只需要回答問題。Phase 3 開始會產出程式碼，需要基本開發環境
原始 .xlsm 會被修改嗎？絕對不會。Skill 硬規定原始檔唯讀，所有輸出放在 migrated/
SQL Server 和 Oracle 都支援？是，Phase 1 自動從 SQL 語法識別資料庫類型，P1 建立對應連線池
如果中途想改決策怎麼辦？告訴 Claude 重新回答 D-X，Claude 會重新產出相關計畫文件
資料庫還沒開放可以開始嗎？可以。每個 P-step 開始前 Claude 詢問 DB 是否可用，選「Stub 模式」即可繼續建 API 並用假資料，前端照常開發。待 DB 就緒後只換 repository 層
Stub 模式的 API 和真實版本一樣嗎？完全相同的路由、請求格式、回應格式。只有資料來源不同（假資料 vs 真實 DB）。前端切換時零改動
怎麼知道哪些 API 還是 Stub？查看 migrated/STUB_STATUS.md，每個端點都有狀態標記（🟡 Stub / ✅ 已接通）
